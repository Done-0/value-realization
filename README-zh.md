# 价值实现（Value Realization）

判断一件事是否真的产生价值——不是凭感觉说好不好，而是落到具体场景，分清哪些结论靠证据、哪些还是假设，看清每个方向探到了多深。

**版本**：2.0.0 ｜ **类型**：分析框架 ｜ **状态**：可用 ✅

---

## 它想解决什么

判断一件事有没有价值，真实的困难很少是「什么都没做」。大多数人都做了动作，问题出在动作的**比重**上——做了，但做偏了、做浅了，自己却不知道。

几种最常见的样子：

- **验证过，但验证对象偏了。** 做产品最开始去找身边朋友聊，朋友愿意捧场、给正反馈，听起来像「验证过了」。但朋友不在你要锚定的场景里，拿回来的是一份位置偏掉的信号。问题不在谈没谈，而在谈的对象跟目标匹不匹配。
- **说了场景，但场景太糊。** 会说「给做营销的人用」，可精度停在这儿，没到「谁、处在什么状态、卡在什么问题上」。场景成分三成、功能成分七成，不是零场景，是失衡。
- **抄了案例，但抄的是表面，还忽略了时间。** 看到别人成功就搬动作，没还原它成立的前置条件。更隐蔽的是时间——两年前成的产品和现在看起来条件一样，实际竞品、平台、用户习惯早都变了，照着做不一定能成。
- **有判断，但分不清证据与假设。** 「看起来成立」，细究下去大部分悬在假设上——一个漂亮却空的判断，而当事人往往不知道它空。

这些都不是非黑即白的失败，而是各占多少比重的问题。真实世界几乎全是半成品加比重失衡，所以判断价值这件事，不能只给「成立 / 不成立」的二元裁决，得能表达程度、能看出哪里糊、糊多少。

## 它站在什么前提上

一个核心判断贯穿始终：**价值不是产品单方面拥有、等着讲清楚传给用户的固定物，而是双方状态在特定场景下共同产生的关系。**

所以「有没有价值」这个问题本身就问错了。对的问法是「在哪个配置里——谁、什么状态、什么条件下——它产生有益属性」。找到那个配置，就找到了价值；找不到，说什么都是空的。

由此又带出几点：一个人算不出完整价值（另一半在真实用户那里）；价值有程度、不是开关；条件带时间、会随环境漂移失灵。这些共同决定了这个 skill 长什么样。

## 它怎么帮你

围绕「价值在哪个场景里产生」这个重心，从四个相互独立的维度把一个模糊的「好不好」拆开：

- **价值场景**——价值在哪个关系配置里产生？（重心）
- **价值条件**——凭什么成立，支撑它的条件现在还在不在？
- **价值时间线**——何时产生，即时还是需要积累？
- **价值传递**——能不能被低损耗地感知到，还是埋在后台传不出去？

每个维度都给两个判断：**方向**（成不成立，🔴🟡🟢）和**扎实度**（多少落在证据上，🟩🟨🟧🟥）。两个分开给，因为一个绿灯可能是「确定成立」，也可能只是「假设成立」——差别很大，而这恰恰是最该警惕的地方。

它不是一份跑完四维就交报告的评估表，而是一个**持续对话的工具**——跟人聊，也跟 AI 聊。每一轮都把靶子聊得更准、把扎实度从「空 / 虚」抬到「半 / 实」，一轮轮逼近一个真正立得住的价值或商业机会。发现价值靠的是犀利地证伪和追问，不是附和与复述。

## 它治的正是自己最想防的病

这个 skill 本身也用它自己的方法立了靶：不知道在打哪个靶、做出来很模糊——这正是它要治的病。所以它要求每次分析都能说清「我在打哪个靶、探到哪、多少靠证据、下一步该去问谁」。

## 适用与不适用

**适用**：判断某个价值主张是否真的成立、产品 / 功能 / 文案 / 场景的价值评估、采用与留存问题、定位问题、把功能对应到具体场景。

**不适用（需谨慎）**：决策者 ≠ 最终用户的企业软件、垄断产品（用户没有选择）、价值本质延迟且条件极稳定的产品。
